# Changes since the last release

## New & Improved

- The in-window menus (the menus of an in-window menu bar and their sub-menus, contextual menus, the dropdowns of `PopupMenu`, `NewComboField()` and `Field.InstallDropdown()`, and the "More Tabs" menu of a dock header) now open in borderless popup windows of their own rather than as panels inside the window that opened them, so a menu is sized and placed within the usable area of its display instead of being clipped to that window. A menu opened from a title on the menu bar still never covers the bar. The popup appears and disappears at once, without the platform's window show animation, and never takes the keyboard focus from the window that opened it. `Windows()` and `WindowCount()` do not include these popup windows, and the standard Window menu does not list them.
- In a headless session, an open menu is a window of its own: `HeadlessScreen.WindowAt()` returns it for a point over the menu, `HeadlessScreen.PanelCenter()` of a menu item lands on it, and `HeadlessScreen.AccessibilityTree()` of that window returns the description of the window that opened the menu, which is where the menu's items are described. `HeadlessScreen.FocusedWindow()` stays the window that opened it.
- `accessibility.Node` has a new `Overlay` field, set on the node of an open menu, and `accessibility.Tree.HitTest()` finds an overlay node and its descendants beyond the bounds of its ancestors, including the window's.

## Bug Fixes

- A menu opened from a title on the in-window menu bar that is taller than the space beneath the bar on its display is now shrunk to fit there and scrolls its items, rather than being moved up over the bar.
- On Linux, a click on the desktop, on a panel, or on another window that takes no keyboard focus now closes an open in-window menu, and a focus-follows-mouse window manager no longer moves the focus away as the pointer crosses one. Previously such a menu stayed open, since no focus change followed the click.
- `PopupMenu.Click()`, the dropdown of a field built with `NewComboField()` or `Field.InstallDropdown()` (whether opened by its button or by the down arrow key), and the "More Tabs" button of a dock header no longer open their menu when the widget's window is not the active one, and `PopupMenu.WillShowMenuCallback` is not run. The menu is opened for the active window, so it previously appeared there, at coordinates taken from the widget's own window, when a screen reader acted on a background window or code opened one of these from it. A screen reader is no longer offered the press that would be refused.
- A menu item that has a sub-menu, including a title on the in-window menu bar, no longer opens it when the item's window is not the active one, whether asked by a screen reader to press or expand the item or by code. The sub-menu is opened for the active window, so it previously appeared there at coordinates taken from the item's own window. A screen reader is no longer offered the press or expansion that would be refused; collapsing an open sub-menu is unaffected.
